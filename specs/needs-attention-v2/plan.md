# needs-attention-v2 實作計畫

規則：實作和審查用不同模型；在隔離 clone 做，PASS 後推 `agent/*` 分支，合併由博元決定；同一件事失敗兩次就停；不動 `~/.hermes`、gateway、launchd。

## 步驟
| # | 卡 | 驗收條件 | 驗證方式 | 依賴 |
|---|---|---|---|---|
| N0 | 確認 Mac 上 agent-watch 版本是否為 `ea3fcd9` 以後，`x` 是否可用 | 回報版本和 `x` 行為 | 看 git log、實按一次 | — |
| N1 | 「其他」根因統計：用真實派工資料，按歸類依據（標籤／git／路徑／關鍵字／無）和未知 project 名計數 | 一張表：每種原因的數量和佔比 | 對照 agent-runs.tsv | — |
| N2 | tok/s 資料來源調查（含 syrtis 報告） | 對照表：每個來源有沒有 output tokens、開始／結束時間、模型名，附真實樣本 | 看樣本 | — |
| N3 | 名稱規則可去多層後綴＋修正卡進行中就算接手＋失敗回到需處理 | fix→fix2 三種情境測試過 | 單元測試 | — |
| N4 | 「已接手」顏色、分區、圖例、標籤「已接手 → 新卡名」 | 截圖可見 | 截圖 | N3 |

| N11 | tok/s 實作（即時＋累計），缺欄位顯示「—」 | 有資料的模型顯示 tok/s；每日 TSV 有平均、中位數、P10／P90 | 截圖＋看檔 | N2 |
| N12 | tok/s 審查 | PASS | 審查報告 | N11 |

## 順序
- 第一波（今晚可並行）：N0、N1、N2、N3、N6、N8。
- 第二波：N4、N5、N7、N9，接著 N10。
- 第三波（N2 查完才開）：N11、N12。

## 風險
- night-dispatch 必填 `--project` 可能讓舊派工腳本失敗：先試派，失敗就給清楚提示，不影響已在跑的卡。
- 名稱規則放寬可能誤認不相關的卡：`--supersedes` 優先；名稱規則只在同專案內比對，加測試。
- tok/s 資料來源可能沒有時間欄位：照規則顯示「—」，寫明做不到的部分。
- Mac 版本落後會讓驗收看錯：先做 N0。

## 回退
每張卡獨立分支；任何一張審查不過，或上線後需處理出現誤判，就回到上一個 merge commit。
